# **Simple CPU in Verilog**

![image](https://github.com/user-attachments/assets/73fa615a-117e-4310-bf4c-5ecbdb8d7784)

## Overview

This project demonstrates a **Simple CPU** designed entirely in Verilog, starting from the most fundamental NAND gates and building up to a complete CPU. The design is available in both **8-bit** and **16-bit** architectures, showcasing how different lane widths affect CPU complexity and functionality. The project is inspired by the [TinyTapeout](https://tinytapeout.com/) initiative, which allows creators to design their own digital circuits and have them fabricated in real silicon.

## Features

- **Gate-level building blocks**: the full adders, ripple-carry adders, bitwise units and the 6-to-1 result mux are built from individual gates. The multiply and divide units are behavioural (`*`, `/`) — a hand-built partial-product tree was tried first but proved numerically wrong (see *Fixes* below).
- **8-bit and 16-bit versions**: same architecture and instruction encoding, differing only in data width.
- **Fully designed in Verilog-2001**: no vendor primitives, no synthesis black boxes.
- **Taped out on TinyTapeout tt08**: the Sky130 GDS, LEF, SPEF, synthesis stats and precheck reports are archived in `Outputs/`.

## CPU Architecture

### Common Architecture for 8-bit and 16-bit CPUs

Both CPUs have the same architecture but differ in the bit-width of their data paths, registers, and instruction sets. Here's a summary of the architecture:

- **Data Width**: 8 bits or 16 bits
- **Instruction Set**: Supports various operations like addition, subtraction, bitwise operations, multiplication, division, and more.
- **Registers**: Multiple general-purpose registers for computation.
- **Program Counter (PC)**: Keeps track of the next instruction to be executed.
- **Arithmetic Logic Unit (ALU)**: Performs arithmetic and logical operations based on the provided control signals.
- **Control Unit**: Decodes instructions and generates control signals for the ALU, data registers, and output registers.

# Control Unit Logic Table

## Overview

The `Control_Unit` module in the CPU design is responsible for decoding instructions and generating the appropriate control signals for the Arithmetic Logic Unit (ALU) and Output Register. It takes an 8-bit instruction as input and produces various control signals, including:

- `acc_we` - Accumulator write enable (only real ALU operations assert it)
- `sub` - Subtraction signal for the ALU
- `op_select` - Operation select signal for the ALU
- `write_enable` - Write enable for the Output Register
- `read_enable` - Read enable for the Output Register
- `output_index` - Index for Output Register operations

## Logic Table

The following table describes the control signals generated by the `Control_Unit` based on the 8-bit `instruction` input. The upper 4 bits (`instruction[7:4]`) are the opcode; the lower 4 bits (`instruction[3:0]`) are the operand address, and for `OUTPUT`/`OUTPUT_READ` the same field selects the output slot.

`acc_we` gates the accumulator: only the six ALU operations write it. Register-transfer instructions (`OUTPUT`, `OUTPUT_READ`) and any unrecognised opcode leave the accumulator untouched.

| `instruction[7:4]` | Instruction | `op_select` | `sub` | `acc_we` | `write_enable` | `read_enable` | `output_index` |
|--------------------|-------------|-------------|-------|----------|----------------|---------------|----------------|
| `0000` | ADD         | `000` | `0` | `1` | `0` | `0` | `00000` |
| `0001` | SUBTRACT    | `001` | `1` | `1` | `0` | `0` | `00000` |
| `0010` | AND         | `010` | `0` | `1` | `0` | `0` | `00000` |
| `0011` | OR          | `011` | `0` | `1` | `0` | `0` | `00000` |
| `0100` | MULTIPLY    | `100` | `0` | `1` | `0` | `0` | `00000` |
| `0101` | DIVIDE      | `101` | `0` | `1` | `0` | `0` | `00000` |
| `0110` | OUTPUT      | `000` | `0` | `0` | `1` | `0` | `{1'b0, index}` |
| `0111` | OUTPUT_READ | `000` | `0` | `0` | `0` | `1` | `{1'b0, index}` |
| others | NOP         | `000` | `0` | `0` | `0` | `0` | `00000` |

The 8-bit encoding reuses `instruction[3:0]` for both the operand address and the output slot, so slots 0-15 of the 32-deep output register are reachable. The index deliberately does **not** include bit 4: bit 4 belongs to the opcode and is `1` for `OUTPUT_READ`, which would make `READ k` address slot `16+k` instead of slot `k`.

## Examples with Expected Outputs

Below are several examples that illustrate the functionality of the `Control_Unit` module:

### Example 1: ADD Instruction

- **Input Instruction**: `8'b00000000` (Opcode `0000`, irrelevant Output Index)
- **Expected Outputs**:
  - `op_select`: `3'b000` (ADD operation)
  - `sub`: `0`
  - `write_enable`: `0`
  - `read_enable`: `0`
  - `output_index`: `5'b00000`

### Example 2: SUBTRACT Instruction

- **Input Instruction**: `8'b00010000` (Opcode `0001`, irrelevant Output Index)
- **Expected Outputs**:
  - `op_select`: `3'b001` (SUBTRACT operation)
  - `sub`: `1`
  - `write_enable`: `0`
  - `read_enable`: `0`
  - `output_index`: `5'b00000`

### Example 3: MULTIPLY Instruction

- **Input Instruction**: `8'b01000000` (Opcode `0100`, irrelevant Output Index)
- **Expected Outputs**:
  - `op_select`: `3'b100` (MULTIPLY operation)
  - `sub`: `0`
  - `write_enable`: `0`
  - `read_enable`: `0`
  - `output_index`: `5'b00000`

### Example 4: OUTPUT Instruction

- **Input Instruction**: `8'b01100011` (Opcode `0110`, Output Index `00011`)
- **Expected Outputs**:
  - `op_select`: `3'b000` (Default operation)
  - `sub`: `0`
  - `write_enable`: `1`
  - `read_enable`: `0`
  - `output_index`: `5'b00011` (from instruction)

### Example 5: OUTPUT_READ Instruction

- **Input Instruction**: `8'b01110101` (Opcode `0111`, Output Index `00101`)
- **Expected Outputs**:
  - `op_select`: `3'b000` (Default operation)
  - `sub`: `0`
  - `write_enable`: `0`
  - `read_enable`: `1`
  - `output_index`: `5'b00101` (from instruction)

### Example 6: Default (Unrecognized Opcode)

- **Input Instruction**: `8'b10000000` (Unrecognized Opcode `1000`, irrelevant Output Index)
- **Expected Outputs**:
  - `op_select`: `3'b000` (Default operation)
  - `sub`: `0`
  - `write_enable`: `0`
  - `read_enable`: `0`
  - `output_index`: `5'b00000` (default)

## Simulation and regression

Requires [Icarus Verilog](https://steveicarus.github.io/iverilog/) (Homebrew: `brew install icarus-verilog`, 2 MB download / 7 MB installed).

```sh
make test     # self-checking: 16-bit CPU, 8-bit CPU, ISA, multipliers
make lint     # compile-only pass with -Wall
```

| Testbench | Coverage |
|-----------|----------|
| `sim/tb_cpu16.v` | runs the demo program built into `Instruction_Register`, checks all 8 output slots, the `uo_out` pin during and after the READ block, and that a PC wrap lands on the NOP padding instead of uninitialised memory |
| `sim/tb_cpu8.v` | loads a 24-instruction program through the pin interface (instructions, then data, with `reset` held), checks all 8 slots and that `uo_out` holds the last slot read |
| `sim/tb_isa.v` | ADD / AND / OR / NOP on the 16-bit core, using instructions loaded through the pins |
| `sim/tb_mul.v` | `multiplier_8bit` exhaustive over all 65536 operand pairs, `multiplier_16bit` over 65536 spread pairs |

Each testbench prints `*** PASS` or `*** FAIL`; `make test` returns non-zero on failure. Waveforms land in `build/*.vcd`.

## Fixes in this revision

| # | Problem | Fix |
|---|---------|-----|
| 1 | `CPU-8Bit-Simplified/` was a half-converted copy of the 16-bit tree: `Control_Unit` and `Address_Register` still took 16-bit instructions, so every opcode decoded as `0000` | 8-bit decode of `instruction[7:4]`, address from `instruction[3:0]` |
| 2 | `OUTPUT` / `OUTPUT_READ` also updated the accumulator (it had no write enable), acting as a hidden `ADD` that corrupted all later results | added `acc_we` to `Control_Unit`, gated the accumulator |
| 3 | The hand-built partial-product multiplier added discarded carry-outs back into bit 0: wrong for 50.9% (8-bit) / 72.2% (16-bit) of operand pairs | behavioural `a * b` |
| 4 | 8-bit `output_index` was `instruction[4:0]`, but bit 4 is part of the opcode and is `1` for `OUTPUT_READ`, so `READ k` read slot `16+k` and never returned what `OUTPUT k` wrote | index taken from `instruction[3:0]` |
| 5 | `Output_Register` only assigned inside `if (read_enable)` with no `else` — an inferred latch | explicit `held_value` register plus a read-cycle bypass mux, and a `reset` |
| 6 | `AND` / `OR` existed in the ALU but no opcode could select them | opcodes `0010` / `0011` |
| 7 | Unused opcodes defaulted to `op_select = 000` (ADD), so a bad instruction silently corrupted the accumulator | default is a true NOP |
| 8 | `instructions[24..31]` were uninitialised, so the program counter wrapped into X | padded with `NOP` |
| 9 | File names did not match module names (`ALU_16Bit (1).v`, `Address_Register  .v`, `or_8bit.v` containing `or8_8bit`, ...) | renamed, one module per correctly named file |

The pre-fix sources are preserved in `../verilog-cpu-sim/orig/` together with a reproduction harness that still demonstrates every bug listed above.
